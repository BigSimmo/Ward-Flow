# Ward Flow checks and evidence

Read when selecting or reporting verification. [AGENTS.md](../../AGENTS.md) governs safeguards; [task-efficiency.md](task-efficiency.md#ward-verification-entry-points) gives the current scoped command entry points.

## Checks and evidence

- Run the smallest check that could catch a plausible regression from this diff. Run nothing for planning or read-only work. Do not stack broad gates or rerun an unchanged passing gate.
- While editing, run `node scripts/run-vitest.mjs run <path/to/test.ts>` so offline defaults and the shared run lock apply (raw `npx vitest` skips both). `npm run test:focused -- --files <a>,<b>` (one comma-separated argument) suits source-only iteration and fails closed to `npm run test`. Current entry points: [task-efficiency.md](task-efficiency.md).
- Before a push, run `npm run verify:pr-local` once (Josh, 31 October 2026: no excessive testing). It runs the cheap document checks, lint, typecheck and only the unit tests your diff affects (`npm run test:related`). Hosted CI runs the full unit suite, the production build, the browser journeys and the backend database tests on every pull request into main, and "Ward Flow required" blocks the merge until they pass, so do not repeat them locally. Add `--full` only when no CI-checked pull request will carry the change before it merges (for example a fix you fold straight into another branch), or when asked. A lean local pass is not a full-suite verdict; report the gates it left to hosted CI as not run.
- One wide run at a time per machine. Narrow checks use the shared run slots. A busy lock belongs to someone else: wait or narrow the check, never force or delete lock state. A run whose process was killed (a closed terminal, a tool timeout) now releases its slot by itself on Linux and macOS once none of its processes are left, so a lock that stays busy is a live run.
- Before running a script, confirm its checkout, base and provider effects suit this repository. A pass in the old checkout proves nothing here.
- Stop servers, browsers and processes you started once the task no longer needs them. Check ownership before stopping one that may belong to another session.
- Paste the decisive output line. Exit 0 alone is not proof. Say what was run, what was read and what is inferred.
- Report reused evidence as reused. A skipped, deferred, previewed or advisory check is never a pass, and missing CI checks are not green. Unknown CI coverage means run the selected gate or report it blocked. A declared workflow is not an observed verdict.
- A focused run is not a full-suite verdict. Local checks do not prove hosted CI, a database connection or a deployment. Chromium evidence does not close physical Safari or installed-PWA acceptance.
- Check a bot's or agent's claim that a fix landed against the actual commit before repeating it.
- Playwright blocking tests run with zero retries. There is no quarantine: `tests/flake-ledger.json` is no longer read (its tooling was retired on 18 October 2026), so a test that keeps failing on the same commit is a real failure to fix or report.
- Test deletion guard: `npm run check:diff-integrity` measures test-case drops against the merge base with `origin/main`. Drops are advisory by default and fail with `DIFF_INTEGRITY_STRICT=1`. Truncation artefacts and an unreadable before-state always fail. Record a deliberate reduction as `{path, before, after, reason, approvedOn}` in `diff-integrity.json`. Never raise thresholds to clear a diff. Detail: [test-deletion-guard.md](test-deletion-guard.md).
- Dead code: "nothing imports it" is not enough. Before removing an exported symbol, run `npm run check:dead-code-candidate -- --diff origin/main`. A refusal fails closed. Only with Josh's explicit approval for that run may you set `DEAD_CODE_OWNER_APPROVED=1` on that single invocation, never as a default or in a script, and record the approval in the PR. Detail: [dead-code-deletion.md](dead-code-deletion.md).

## Checks that cannot run in agent checkouts

Some checks need things a cloud agent checkout often lacks. Report them as blocked or unavailable, never as passed.

- **Full git history.** `npm run check:dead-code-candidate` and `npm run check:stale-docs` refuse on a shallow clone (`git rev-parse --is-shallow-repository` prints `true`), because they date files and symbols from commit history. `npm run check:diff-integrity` needs a merge base with `refs/remotes/origin/main`, or an explicit `--base <commit>` / `DIFF_INTEGRITY_BASE_SHA`; a missing or unreadable base fails closed. Workaround: deepen the clone to the depth the refusal names (`git fetch --deepen=2000` or `--deepen=3000`), or `git fetch --unshallow origin main`. That is network Git, so ask Josh first ([AGENTS.md](../../AGENTS.md) hard rule 3). Without that yes, report the check as blocked.
- **Browser revision.** `npm run check:playwright-browser-revision` fails with `container-revision-drift` when `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` holds an older Chromium than the installed `playwright-core` expects. Never point `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` at the stale shell to clear it. Workarounds, as the script prints them: leave browser proof to hosted CI, refresh the image or run `npx playwright install` into a matching cache (a download, so it needs a yes), or unset `PLAYWRIGHT_BROWSERS_PATH` and `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD` to use the managed cache. `scripts/run-playwright.mjs` falls back to the newest preinstalled container shell on its own and logs that it did; a run that used the fallback is not evidence for the pinned revision.
