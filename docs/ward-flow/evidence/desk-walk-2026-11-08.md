# Desk-by-desk browser walk, 8 November 2026

**Audience:** Josh and builders. **Status:** point-in-time evidence; not refreshed. **Owner:** Documentation.

Roadmap step 1 of [Finish role access (D-80)](../roadmap.md#1-finish-role-access-d-80): walk each desk on synthetic data and check it sees only what D-80 allows. This is a first automated pass, not the full walk, and not Josh's review.

## How it was run

- Source: `main` at `d85618e6`, plus the uncommitted D-80 item 17 change on the same branch (it touches the Discharges board and the Capacity ward drawer only).
- Local dev server (`npm run ensure`), local synthetic demo, role access flag on (`?flags=role-access:on`). No shared server, no sign-in back end and no provider was used.
- Headless Chromium 1440 x 900 through Playwright. Each desk was set the way the tour spec sets one (`wardflow:access-desk-v1` in session storage), with every tour marked seen.
- For each desk: open `/ward-flow`, read the links in the rail's "Ward Flow views" menu, then open every menu screen in a fresh tab and wait for the network to settle plus 2.5 seconds. A screen passes when it opens without page errors or console errors, is not the "Not part of your role" page, and its heading names the desk's own place where it has one.
- Leak probe: each other desk also opened the coordinator's menu screens that are not in its own menu. Those should be closed or show only that desk's own place.
- Desks: coordinator (statewide), site bed manager (FSH), nurse in charge (FSH Adult Secure), ED (FSH ED), community (Albany team), transport officer, executive (statewide), access admin.

## Things to look at

1. **Open by address, not in the menu.** The ward, ED and community desks can open Waiting (all three), Movements (ED, community) and Handover (ED) by typing the address. Each showed its own place or zero counts, so no other place's patients were seen. Whether these should be closed like Capacity is a product question for Josh.
2. **First paint shows network figures.** The server renders each page as the whole-network coordinator before the browser applies the desk (the raw HTML of `/ward-flow/capacity` holds "beds ready of 304"). With a shorter wait (about 1.6 seconds after the network settled) the bed manager's Capacity still read "26 beds ready of 304", and the officer's and admin's Movements showed content before closing. The executive's closed screens sat on "Loading the executive view" for more than 2.5 seconds before closing. In the local demo all data is synthetic and already in the browser, so this is not a leak there; it needs checking on a production build and in shared mode before real data.
3. **Not covered.** Patient, movement and referral detail pages, break glass, cover, the phone layout and the shared signed-in server were not walked. The dev server was stopped twice by the machine running out of memory (other work on the same machine); the affected desks were re-run and the table is from the complete final run.

Screenshots were not kept. The walk scripts and their JSON output stayed in the agent's scratch folder and are not part of the repository.

## Follow-up fixes, 9 November 2026

Josh approved fixing both findings. Branch `fix/desk-route-scope`; checked on a local production build (`WARD_GATE_BUILD=1`, `next start`), headless Chromium, synthetic demo only.

1. **Open by address.** Only the community desk's Waiting is now closed (`ROLE_SCREENS` in `ward-role-access.ts`, the why-can't-I guide and `tests/ward-role-access.test.ts`). It had no community view and showed zeros; the team's own waiting referrals are on My team. The others stay open because they are intended, and they sit under each desk's **More**, which the walk did not read: community Movements (D-80 item 5, community desk guide), the ward's and ED's own Waiting views (built 31 October 2026), the ED's Handover branch (approved Handover redesign, 31 October 2026) and the ED's Movements (first in its More list).
2. **First paint.** Cause: the desk lives in the tab's session storage, which the server cannot read, so the server drew every page, rail and top bar as the whole-network coordinator. The existing first-load hide covered only the page area. Now a stored desk other than the whole-network coordinator's also sets a cookie holding only "1" (`wardflow-desk-held`). With it, the server sends the neutral "Loading page" placeholder instead of the page, rail and top bar, and the browser draws them once it knows the desk. A fresh device and the coordinator keep the server's page (H-0111).
   - Checked for the site bed manager, nurse in charge, ED clinician and community team on Capacity, Home, Waiting, Movements and Handover. The raw server HTML held none of the coordinator's figures or name ("of 304", "across the whole network", "62 waiting in ED", "70 still open", "7 awaiting a decision", "East Metro 87%", "Dr S. Chen"). No painted frame showed them, sampled every animation frame for 9 seconds. There were no page or console errors, and each page settled on the desk's own view or "Not part of your role". The coordinator's own pages were unchanged.
   - **Still open.** The very first load after a desk is set outside the app (as this walk did), or in a second tab after another tab chose the coordinator's desk, has no cookie yet. The server's HTML then still holds the coordinator's figures. The page area stayed hidden and no figure was painted, and the cookie is set for the next load. On a held load, the rail and top bar appear only when the page's code runs.
