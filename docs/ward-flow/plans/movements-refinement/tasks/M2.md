# M2 — bounded source review

Compared `.superpowers/sdd/movements-refinement/before/movements/` with the current `movements/**` implementation and traced the changed populations through the existing movement, closure, decline, owner, stage, transport, and route contracts. This review excludes the Day metrics, orthogonal schematic, key, summary keyboard behavior, and restored Transport detail rows already being corrected by M1/root.

## Findings

### P2 — stage groups are published as unique active corridors

`corridorCounts()` keys accepted movements by `(originEdId, acceptedUnitId, stage)` (`movements-derivations.ts:311-360`). Two open movements using the same origin/destination route at different stages therefore produce two rows. The screen and diagram then use `corridors.length` as the number of “Active corridors” (`movements-screen.tsx:87-90,182,209`) and as the accepted-corridor figure exposed by the diagram and its switcher (`traffic-diagram.tsx:82,178-180`). One physical origin/destination corridor can consequently be counted two or more times. The neighbouring Declined derivation groups only by `(originEdId, unitId)`, so the Accepted and Declined switcher figures also count different units.

Smallest repair: preserve the stage-specific rows needed for line/tool-tip detail, but derive every published corridor total from distinct origin/destination pairs. In the ranked register, group stage rows under that pair or explicitly distinguish “corridors” from “stage rows.” A two-movement case on one pair at two stages should read one active corridor, two active movements, and two stage entries.

### P2 — “Shape of the open day” contains resolved, closed movements

The summary panel is titled “Shape of the open day” and carries an `${openMovements.length} open` panel count (`movements-screen.tsx:408`). Four views use open populations, but Resolved is populated from `closedToday` (`movements-screen.tsx:415,469-470`). Switching tabs changes the region from the population promised by its persistent heading to a disjoint closed population while that heading and count remain unchanged.

Smallest repair: name the container for the mixed scope, such as “Shape of the day,” and let each tab state its own population. Keep Stage, Transport, Waiting, and No owner explicitly open; keep Resolved explicitly closed today. Do not merge the counts.

### P2 — a requested transport job is presented as a booked leg in the worklist order

The worklist’s Transport order divides every movement using only `movement.transport !== undefined` and labels that group “A transport leg is booked” (`movements-screen.tsx:92-99,309-338`). `BOOK_TRANSPORT` can create a transport record without `acceptedAt`; the existing `transportLegs()` contract in the adjacent derivation deliberately excludes that Requested state because a provider has not accepted and no honest booking time exists (`movements-derivations.ts:227-285`). Immediately after a request is recorded, the worklist therefore says the leg is booked while the Transport summary correctly says it is not.

Smallest repair: split the worklist using the canonical transport state and `acceptedAt`: booked/accepted legs, requested or pre-acceptance-cancelled records, and no transport record. If the UI must remain two groups, use “Booked transport leg” only for records with `acceptedAt` and give every remainder wording that does not erase an existing request.

## Closure review

All three findings are resolved in the settled source.

- Published active-corridor totals now use distinct origin/destination pairs. The schematic retains its stage-specific paths, while the accepted register aggregates each pair's movement count and exposes the contributing stage counts below it.
- The mixed-population panel is now titled **Shape of the day**. Its heading count changes to the same-day resolved population on Resolved and otherwise states the open population used by the other views.
- The worklist's Transport order now partitions records into provider-accepted legs, unaccepted transport records, and no transport record. The summary uses the same semantic split; requested and pre-acceptance-cancelled records carry an explicit **Not accepted** clock and are no longer described as booked or awaiting acceptance.

This closure is a source-only verdict. No test or browser command was run by M2. The coordinated browser navigation attempt was blocked by `ERR_BLOCKED_BY_CLIENT`, so the final visual delta remains unverified rather than accepted from source inspection.
