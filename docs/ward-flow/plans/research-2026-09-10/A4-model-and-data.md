## 5. Persistence and reset

**No localStorage for clinical/demo state — confirmed [src].** `WardFlowState` lives only in a
`useReducer` (`ward-flow-provider.tsx:269`), seeded by `seedWardFlowStateAt`. **A page reload wipes
every interaction back to the seed** — there is no write path to any storage for `movements`, `patients`,
`admissions`, `referrals`, etc. The only `localStorage` keys under `ward-management/` are UI
conveniences unrelated to clinical state: `community-index.tsx:538` (recently-opened strip),
`hub-browser-memory.ts:14` ("NOTHING SHOULD BE" written there beyond ids), `use-ward-sidebar-collapsed.ts:9`
(sidebar collapse flag). **In-app reset:** `RESET_SCENARIO`/`SET_SCENARIO` (reducer.ts:936/939) call
`seedWardFlowStateAt` again, same effect as a reload. A one-time client/server hydration reseed also
occurs at mount (`ward-flow-provider.tsx:170-260`, `WardFlowProvider`'s `adopted` effect) to avoid SSR
clock mismatch — deliberate, documented, unrelated to data loss.
