### Identities and invariants

Patient (`PT-*`), front-door referral (`RF-*`), movement (`WF-*`), admission (`AD-*`), release (`WR-*`) and leave (`WL-*`) are different records. A referral can intentionally lack patientId. A movement joins through referralId and optional admissionId. Runtime admission creation copies patient/referral provenance when available and retains movementId; seeded unknowns must remain unknown. Display resolution must follow those links only: WFA-007 violates that invariant.

Required invariants assessed:

1. A pointer names an existing, corresponding record; an absent link never selects a different person. **Fails** WFA-004/WFA-007.
2. Pull allocates once, arrival converts the same hold, physical departure/release restores the correct resource once. Ordinary repeated-pull guards exist; composed correction paths fail WFA-004, locked-kind restoration fails WFA-003.
3. Correction of a stage never erases a physical collection, admission or resource obligation. Preserving resources on step-back is the owner rule; WFA-001/WFA-004 concern subsequent actions, not that rule.
4. Ready, held, blocked, occupied, preparing, expected release and leave are distinguishable. `unitCapacity` derives Ready as min(allocatable, empty), Held as empty minus Ready, and Occupied from total minus empty minus blocked. `openBedsNow` additionally subtracts discharged-but-preparing releases. Different measures are intentional, but displays/decisions must name the measure and use it consistently; WFA-008/WFA-010 remain concerns.
5. Locked/open kind is conserved. `lockedBedsFree` clamps the recorded locked amount to total allocatable; `openBedsFree` subtracts it. These helpers do not repair a lost underlying count (WFA-003).
6. Staffing counts pulled and occupied admissions, including specialling/high acuity; guards run at pull under the later owner ruling. Capacity is not reserved twice merely because acceptance is recorded. Overrides must retain reason/actor/time and NUM consultation where required.
7. Event occurrence, recording, expiry and freshness are not interchangeable. Zero is present; unknown is not zero. WFA-002 fails presence; WFA-005/WFA-006 fabricate displayed facts. No statute-derived duration is validated here.
8. Cancellation does not invent a replacement job or handover readiness. Precollection cancel and explicit rebooking exist. After collection, stop records whereabouts and holds the bed until separate release. WFA-004 bypasses that separation.
9. A refused action preserves clinical/resource state while appending refusal/audit evidence. Client-side reducers are synchronous within one tab; separate tabs are separate worlds, not concurrent users of one stock ledger.
10. Acknowledging a task does not make a live hazard disappear. Inbox code separates facts from completable commitments. Handover cannot substitute for an independently recorded receiving clinical responsibility.

## 4. Findings register

Severity refers to the potential effect if relied upon operationally; all observed data/actions were synthetic. Priority P1 precedes P2. None of these findings is marked fixed by this task.

### WFA-001 — Cancellation describes a retained bed as absent

- **Severity / priority / status:** High, P1, recommended. Historical WF-02/WF-04.
- **Journey / screens / roles:** J2–J3; ED, transport, coordinator/ward notices; ED/coordinator/booking owner.
- **Observed / reproduction:** pull → book → step back to accepted_awaiting_bed → cancel. Admission/hold remains but blocker says awaiting a bed and cancellation notice says no bed held.
- **Expected / authority:** step-back owner ruling preserves resources; 17 September cancellation ruling requires truthful cancellation without automatic rebooking.
- **Evidence / root cause:** locally reproduced by one diagnostic case. `ward-flow-reducer.ts` CANCEL_TRANSPORT derives bedIsHeld from stage index, not the admission/hold. `ward-cancel-transport-no-bed-held.test.ts` mislabels a step-back fixture as a released bed; its releasedNoBed helper calls the same stepped-back state.
- **Impact / resolution:** coordinators can seek a second bed while one remains held. Determine held status from actual commitment, preserve seeded unknowns explicitly, and make the existing test's no-bed fixture genuinely release its hold. No test was weakened or changed here.
- **Verification:** one intended assertion fails on the current reducer; no repaired or browser cancellation result claimed.

### WFA-002 — Zero-valued transport milestones block or repeat progression

- **Severity / priority / status:** High, P1, recommended. Historical WF-39.
- **Journey / screens / roles:** J3; officer job and receiving ward; officer/ward.
- **Observed / reproduction:** acceptedAt=0 fails en-route precondition; enRouteAt=0 fails collection; collectedAt=0 fails arrival. Repeat acceptance/en-route at zero is treated as absent and can overwrite the milestone.
- **Expected / authority:** Instant is minutes from day-zero, so zero and negative values are valid; undefined represents missing. Existing UI/transport derivations already use explicit presence checks.
- **Evidence / root cause:** locally reproduced, five failing diagnostic cases; reducer milestone truthiness near 3927, 3990–4056 and 4110.
- **Impact / resolution:** a midnight journey becomes stranded or loses its original milestone. Use explicit presence checks consistently in engine and consumers; retain chronological tests including zero, negative, positive and missing. The five probes isolate presence/repetition, not all timing chronology.
- **Verification:** diagnostic assertions failed as intended; no fix, no browser midnight simulation.

### WFA-003 — Departure loses locked-bed availability

- **Severity / priority / status:** High, P1, recommended.
- **Journey / screens / roles:** J4 returning capacity to J2; ward discharge, matching, capacity/network; ward/coordinator.
- **Observed / reproduction:** secure locked pull → booking/handover/collection → arrival → RECORD_LEAVING. Total allocatable returns to six; locked free remains five instead of six in the controlled fixture.
- **Expected / authority:** known Admission.bedKind and the owner's open/locked accounting contract; release of that exact resource restores its kind once.
- **Evidence / root cause:** locally reproduced by one case. PULL_PATIENT decrements allocatableLocked, reservation release restores it, but shared departAdmission restores only total/empty/sex mix. Both protected discharge and legacy leaving use that helper.
- **Impact / resolution:** repeated secure discharges silently reduce apparent locked capacity and can misclassify freed capacity as open. Restore known locked kind exactly once; do not guess the kind of old admissions whose provenance is absent.
- **Verification:** one failed diagnostic, ordinary helper path source-inspected; no repair.

### WFA-004 — Stage correction permits unsafe release and dangling admission links

Required independent evidence includes clinical hazard ownership and clinician-led scenario acceptance; privacy/security assessment of identity, access, storage, retention and audit; Aboriginal cultural safety review of identity/demographic display and placement experience; accessibility review with assistive technology and representative users; legal review of legal-form/authority wording and supported pathways; medical-device classification assessment; maintained authoritative catchment/service directory; and operational governance for staffing, bed reconciliation, transport failure, handover, downtime and escalation. These are readiness gates, not new thresholds or statutory rules invented by this audit.

The existing deferral of Aboriginal cultural safety review is preserved, not reopened as a question. A synthetic disclosure or “not a medical device” label does not itself settle any of these external assessments. No recommendation here authorises real-patient use or deployment.
