## Verified good under pressure (evidence-backed, no defect)

- **Double dispatch of state-machine events refused, not corrupted**: `FLAG_MOVEMENT_URGENT` #2, `CONFIRM_CAPACITY` stale revision, `CONFIRM_BED_RELEASE` #2 ("cannot move this bed release from confirmed to confirmed"), duplicate `RECORD_PATIENT_DISCHARGE` ("Someone else changed this record first"), all with Rejection rows.
- **Staleness refusal UX**: wrong `expectedGeneration` → "The board was reset or replaced since you opened this. Check the board, then try again. Nothing was changed."
- **Boundary payloads refused with reasons, never truncated**: correction note blank/whitespace/2001-chars (limit 2000 enforced exactly); broadcast empty title / whitespace message / duration 0 / −5; UMRN empty & whitespace; upload sizeBytes 0/−5/2⁵³ (behind the fileType guard — size guard verified with a valid type); blocker blank/whitespace; `ADVANCE_CLOCK` negative.
- **Capacity extremes**: confirm at −1 and beds+1 refused; 0 accepted; pull at zero allocatable refused with a precise reason and the override path does **not** invent a bed ("no Ready bed remains… allocatable 0, physically empty 2").
- **Refresh mid-action (code-level)**: actions dispatched before the saved day is adopted are replayed via `preAdoptionEvents` and "a now-stale action is refused on screen rather than lost" (`ward-flow-provider.tsx:975-1003`); `beforeunload` warn when typed text is held and saving is off; scrubbed device copy v7 written per committed change (`ward-flow-demo-storage.ts:236`), refuses unsafe/invalid copies.
- **Zero-bed / empty-ward**: scarce scenario clamps live; capacity 0 confirm + pull refusal behave correctly (probe3 S1/S5).
- Integrity across all rounds: `patients 362→362`, `movements 77→77`, `worldGeneration` stable except documented scenario bumps, `rejections` grew only by refusals.
